## 1. 结论与候选顺序

**已经找到明确的矩形 AMOLED 配套，不需要先购买普通 LCD。** 官方的 1.85inch AMOLED Module 使用 ZC-A1D85W-010 面板，390×450，支持 SF32LB52 的 Nano、Core、DevKit-LCD 和黄山派。[S1]

**首选核价组合：SF32LB52-DevKit-Nano-R16N16 + 官方 1.85inch AMOLED Module + 对应屏幕转接板及 16P 排线。** 依据是较小板型、16MB PSRAM、16MB NOR、已公开的显示/触摸接线，以及可供传感器扩展的引脚。其电池供电、传感器和振动需要补接，不能当作完整手表套件。[S1][S2]

| 候选 | 已有证据 | 对本项目的主要代价 | 当前定位 |
|---|---|---|---|
| Nano-R16N16 + 官方 AMOLED 模组 | 21×51mm；16MB PSRAM + 16MB NOR；官方板屏配套 | 外接 PPG、IMU、振动驱动和电池电源；测量隔离点需核对原理图 | 首选核价，较接近后续粗糙佩戴原型 |
| Core-3p3-R16N16 + 同一 AMOLED 模组 | 30.88×68mm；同为 16MB + 16MB；有分电源测量跳线和对应 AMOLED 功耗例程 | 主板更长；同样需要外接传感器及电池电源 | 功耗台架备选，不默认与 Nano 同时采购 |
| DevKit-LCD N16R8 + 同一 AMOLED 模组 | 8MB PSRAM + 16MB NOR；充电电路、扩展排针；手表示例列入支持范围 | 音频、调试等附加电路需识别；电源版本与充电配置需确认 | 若有价格合适的现成完整套装，可比较 |
| 黄山派 / DevKit-ULP + 配套 AMOLED | 已列出六轴 IMU、环境光、振动驱动、电池路径和测量接口 | 当前供货不明；文档同时存在“内部试用”和淘宝购买入口 | 集成程度高的条件候选，不能按已有现货排期 |

这个排序是工程判断，不是平台性能排名。若黄山派能提供明确版本、现货和预算内的完整报价，值得优先重新比较，因为可以减少扩展接线。若 Nano 的完整供电/测量路径难以成立，而 Core 套装有可复现的对应例程，才考虑以 Core 替换首选。

Nano 的 51mm 长度和 Core 的 68mm 长度都不能证明佩戴舒适；屏幕、转接板、电池叠层还会增加尺寸。两者首先是开发原型，不是 Redmi Watch 4 外形的现成替代。Core 尤其可能增加后续结构返工。

我的判断：其开放范围足以支持本项目的短周期应用验证，尚未发现必须修改封闭部分才能完成首版的证据。但“能定位故障”有边界：可以定位到协议交互、调用顺序和底层异常表现，落入封闭固件内部时，可能仍需依赖厂商修复。它不是完全开放的无线平台。

传感器首版安排为 HCPU 按需处理，使用外部传感器的 FIFO、中断及自身低功耗模式减少唤醒。是否能满足整机功耗预算，交由实测；不以存在两颗核推导“传感器后台可以免费运行”。

## 4. 扩展、保存与电源路径

### Nano 的传感器扩展

Nano 文档列出侧边引脚 PA24、PA25、PA28、PA29、PA30 等，以及另一侧 PA37～PA44；支持可配置 I2C 和定时器功能。已有显示使用 PA0～PA8，触摸为 PA20/PA11、PA9 中断、PA10 复位，调试使用 PA18/PA19。[S2][S9]

因此，PPG 与 IMU 共用一组额外 I2C、分别使用中断，再保留传感器电源控制和电机控制，在引脚数量上有明确路径。具体分配仍需同时核对 PCB、pinmux、按键/LED/音频默认配置，不能直接把这段描述当接线图。六轴 IMU 应选择带 FIFO、中断及通道低功耗配置的器件；六轴齐备不要求陀螺仪常开。

新购 MAX30102 模块需核实板上稳压、IO 电平、上拉电源和 LED 供电；裸芯片与模块不能按同一种电压接线。已有 F411 手表中的 MAX30102 先用于策略实验，不能把其整板电流代替新平台传感器负载。

振动需要电机与相应驱动，GPIO 只作控制。新增传感器电源开关时还要检查 I2C/中断引脚的反向供电；否则软件“关闭采样”未必减少板级耗电。

### RTC、内存与夜间数据

Nano-R16N16 和 Core-R16N16 都有 32.768kHz 晶体、RTC 路径及 16MB NOR；DevKit-LCD N16R8/黄山派为 8MB PSRAM、16MB NOR。注意 128Mb 等于 16MB。[S2][S3][S4][S5]

390×450 的 RGB565 单帧缓冲为 351,000 字节，双缓冲为 702,000 字节。16MB PSRAM 有应用空间，但字体、图片、合成缓冲、栈和碎片仍需实测；PSRAM 也不能用作断电后的持久保存。

NOR 需为固件、资源、配置、可能的升级区和采集数据划分分区。以下只作数据预算样例，不代表算法输入已经满足：

- 8 小时每 10 分钟记录一次，48 条，每条 32 字节，约 1.5KB；这只包含稀疏摘要。
- 假设 PPG 两通道各 3 字节，六轴 IMU 各 2 字节，均按 50Hz 保存：30 秒原始片段约 27KB；20 段约 540KB，另加时间戳、质量、校验与文件开销。
- 可先尝试预留 2MiB 环形数据区，前提是链接与分区结果确实有余量；规定摘要保留期、片段上限和空间不足时的覆盖规则。

首轮要验证写入、重启读取、断电后记录完整性、空间满处理及手机读取。不能把“有 16MB Flash”当作已实现数据链路。每 10 分钟一次心率是否支持未来睡眠分期仍未证明。

### 供电与测量

- Nano/Core 的文档提供 USB、5V/3.3V 输入路径，未据此确认完整的锂电池充电保护方案。电池阶段需要匹配的稳压、充电和保护路径；不能把单节锂电直接接到 3.3V 输入。[S2][S3]
- Core 明确提供单路电流和整板测量跳线，适合定位功耗；Nano 需要先核对调试芯片、LDO、LED 和屏幕电源是否随测量一起计入。
- DevKit-LCD 的 ETA9640P 默认充电电流为 450mA；黄山派文档也列出默认 450mA。两者均推荐约 450～500mAh 电池。这不能直接证明任意 300mAh 电池可安全使用；应核对电芯规格、充电终止电压、充电电流及保护配置。[S4][S5]
- DevKit-LCD 有不同模组电源定义，VBAT 与 3.3V、输入与输出不可混用。实际板卡版本是接线前置条件。

官方 AMOLED 例程报告过 Core 上的低功耗测量，并给出拆分供电接法。这支持“有可操作的验证路径”，不证明我们的整机续航。其条件为 5V 供电、特定画面和周期唤醒，未覆盖本项目 BLE、PPG、振动与 45 分钟复杂交互；文档中也存在汇总表与正文算式不一致的地方，不能直接引用其天数作承诺。[S12]

跨电压轨比较时用能量：`每日 mWh = 各状态电压 × 电流 × 持续小时之和`，再计入电源转换损耗。300mAh 电池若仅以 3.7V 标称电压估算，预留 20% 后七天每日约 126.9mWh；最终仍应测电池侧实际能量。不能将 5V 侧测得的 mAh 直接除以锂电池的 300mAh。

首轮还需确认借用电流探头的型号、最低量程、零漂和带宽；资料中有微安级结果，不表示现有磁场式探头一定能测准。

| 4h | 核对 PPG/IMU 供电与中断、振动驱动、RTC 和 NOR 保存路径 | 接线/冲突表及写入、重启读取结果；有实物再测传感器事件 |
| 4h | 合并证据和故障复现，作继续/限时补试/换路线判断 | 主要耗电项、缺口、下一项实验及预算 |

两个必须提前验证的相互影响：触摸和 UI 定时器能否随熄屏正确退出；BLE 保持连接时，HCPU 是否仍可休眠、通知是否能按需唤醒。不得将分别跑通的 UI 示例和最低功耗示例当作同一系统已通过。

当前结束状态：板屏兼容性有官方证据，开放范围和扩展路径已收敛；采购仍等待准确 SKU/版本、黑边与电气尺寸资料、完整现货报价。平台实测、七天续航和 Gadgetbridge 兼容均未验证。
