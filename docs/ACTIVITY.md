# 活力指标与计步页面

## 第一轮契约（2026-10-19）

用户提供12张Redmi Watch 4实拍，并确认先完成页面与入口，全天原生计步另轮接入。参考照片只提供视觉与交互，不证明任何算法、健康阈值或本板能力。

- `activity`、`steps`、`calories`、`standing`、`active_minutes`为五种稳定组件身份；保留既有steps／standing布局记录。活力指标支持half／full，其余支持quarter，各有既有两种配色。它们都进入同一`ACTIVITY`页面，首次进入位于总览；Product应用菜单只展示一个活力指标入口。
- 390×450黑底页面，顶部三色半圆进度及三项摘要，随后为卡路里、步数、中高强度活动、站立卡片，底部数据说明。四张卡片各410px高、间距16px，连续竖向滚动，禁止吸附。总览前三环分别对应卡路里／步数／活动分钟，站立独立成卡。
- 数据说明为独立长文页，返回保留父页滚动像素位置。离开整条路径后按既有生命周期释放；重新打开从总览开始。左边缘右滑、KEY1、DIM／短睡／长睡和提醒恢复沿用系统契约，不申请常亮或新增定时器。
- 以已有中性色板绘制卡片，不把照片偏蓝当作新增主题。XML及官方生成物拥有布局；`activity_view.c/h`只绑定值、目标、进度和图表柱高，不创建另一套布局。

## 数据边界

`core/activity.h`是本轮显示输入契约，没有采样、算法、后台worker或存储。四项总量、目标和24小时桶独立有效；缺数据为`--`，真实零为`0`。缺失小时不绘柱、不冒充0，全部无小时记录显示“暂无数据”；最大值仅计算有效小时。目标为正且总量有效才绘制进度，超过目标封顶100%，原始总量保留。

Product目前不提供活动数据，因此四项数值／目标缺失，环与图表保持空态。限时诊断的70步不接入此页。示例总量与目标只在独立UI Demo源文件中组装，不编入Product；样例目标不构成健康建议或用户已设目标。数据说明只解释字段与缺失值，不复制参考表的健康建议或未经验证的判定阈值。目标编辑、全天累计／跨天／时区／重启持久化、卡路里／站立／强度算法都属于后续各自闭环。

下一轮真实生产者必须另行确认当日归属、来源／时间／版本、同步复制、原生计数所有权、跨天及恢复规则；本轮显示结构不是已完成这些决定的证明。硬件路线继续遵循[能力门槛](HARDWARE-CAPABILITIES.md)。
