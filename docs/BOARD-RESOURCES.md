# 板载资源开发规划

2026-10-23规划轮，依据[六项方向](BASELINE.md#next-six-20261021)及用户本轮补充。本文保存范围、依赖与验收契约，不维护另一份活动队列；活动项与唯一下一步仍见[STATUS](STATUS.md#current)。源码调查基线为`4190c9c`，SDK／子模块保持[sdk.lock.json](../sdk.lock.json)锁定版本。本轮只做资料／源码检查和规划，不修改固件、不构建、不操作设备或购买物品。

## 已确认顺序与物料

每个器件按 **硬件跑通 → 对应页面 → 具体功能接入** 形成独立闭环。先取得真实输入／输出及停止恢复证据，再做页面，最后接入产品策略；不先把全部新页面做成占位，也不把识别成功当作功能完成。计步与抬腕已有分版本设备证据，本阶段不重新实现；其共存状态只在受影响路径定点核对。

用户确认已有TF卡、没有喇叭，音频应先采购。板卡已有MEMS麦克风／Class-D功放，采购准备先核匹配喇叭和连接件，不重复列麦克风、功放或TF卡。音频具体功能的先后尚未确定，不把此前建议的“声音提醒→录音→音乐”写成用户决定。

开发建议顺序为光感→地磁；喇叭规格／采购准备可同时推进，TF在音频文件需求前跑通。喇叭到手后再进入完整音频硬件轮。KEY2／RGB属于低优先级配套项，先验证、再按实际用途决定设置及功能，不为利用器件强造独立应用。GitHub展示按用户顺序放在本阶段之后；已有参考调研继续沿用。

## 当前能力与接入缺口

以下是配置／源码事实，均不是本次器件实测通过。

| 资源 | 已有基础 | 当前缺口及承重依据 |
|---|---|---|
| LTR-303ALS-01环境光 | 板载；SDK传感器示例支持黄山派，I2C3／PA39、PA40，地址0x29 | Product未消费光感数据。`LTR303.c:139–143`只返回CH1原始值，而`sensor_liteon_ltr303.c:101`标为LUX；必须先查数据手册、双通道／增益／积分时间／数据有效性及换算，不能直接采用该单位标签 |
| MMC5603NJ地磁 | 板载；SDK驱动地址0x30、ID寄存器0x39／期望0x10 | Product未消费地磁。SDK compass示例把PA39／40设成I2C2，不能直接搬入当前I2C3；XYZ读数、校准、坐标、倾斜影响与可信磁北方向分别验证，不以`atan2(y,x)`演示当精度证据 |
| MEMS麦克风／音频PA | 官方板卡页确认板载；锁定board.conf选择AW8155／PA42，底层AUD PRC／CODEC存在 | SDK配置不是实物料号核验，精确MIC／PA型号及模拟连接仍需原理图／实物核对。Product未接录放音业务；官方record示例的支持列表未列黄山派，不能直接宣称可用 |
| TF卡座／已有TF卡 | 板载SPI1卡座，PA24／25／28／29、检测PA27；用户有卡 | 没有本项目读写／挂载证据。不能把其他板的SDIO／SDMMC示例当成SPI卡路径已通；卡型号、容量、文件系统及既有文件待使用前盘点 |
| KEY2 | 板级定义PA43有效高；已有生成配置含KEY2 | Product尚无KEY2业务消费；生成配置是旧产物记录，下一次构建重核。需要先分清实际两个按键，不能混淆KEY1短按／唤醒及长按复位 |
| RGB | 资料为WS2812B-2020／PA32，和电机共用VDD33_VOUT2／LDO3供电 | `product_motor_board.c:11–13`主动禁止RGB与当前电机借轨逻辑同时编入。这是资源保护，不是待绕过的驱动错误；独立验证前须确定共享供电责任，不能删除守卫就算接入 |

传感器示例位置为`vendor/SiFli-SDK/example/rt_device/sensor/`；LTR／MMC驱动位于`customer/peripherals/sensor/`。本轮未取得这些新资源的Product设备结果。IMU旧证据与其他示例运行不抵扣新器件验证。

## 各器件的三个闭环

| 器件／方向 | ①硬件跑通 | ②对应页面 | ③具体功能接入 |
|---|---|---|---|
| 光感→自动亮度 | 显式限时读身份／CH0与CH1／配置／新鲜度，观察遮挡、室内与较亮环境响应；说明饱和／无效，按数据手册核单位。停止采样并恢复，确认计步／抬腕和关亮屏共存；没有照度计时不声称绝对lux精度 | 改已有“屏幕亮度”页，呈现自动／手动入口和真实可用状态；确定自动状态下手动项的含义，不额外造光感应用。官方XML预览／导出，真实LVGL检查返回／草稿／无效显示 | 实现有限采样、平滑／滞回及上下限、故障回退和偏好保存。手动值与自动计算值分开。建议只作用正常显示，手电筒强制全亮、AOD固定低亮及长续航边界单列；实施前确认交互细则，不用自动亮度反复唤屏 |
| 地磁→指南针 | 身份／连续XYZ／数据有效性、静置与受控旋转响应，核量程和传感器相对屏幕轴向；按精确器件资料评估原生SET／RESET／自检。完成停止恢复／共享总线检查 | 指南针主页面及校准引导，明确校准中／不可用／受干扰状态；先用已验证快照，演示角度仅放UI Demo或主机。先确认外观与交互，不把未校准方向画成可信结果 | 先交付平放磁北方向与校准／有效性，再评估倾斜补偿；需要时复用既有IMU数据来源。基准方向和干扰场景有界核对，离页停止无消费者的采样；不推导海拔／位置或无来源的真北偏角 |
| TF→本地存储 | 先盘点／只读识别和读取既有文件；采用精确板SPI路径，再用独立新建测试文件有限读写、关闭并读回。保留已有文件，不自动格式化；处理无卡／I/O失败／停止，真实拔卡仅在确认文件关闭后验证 | 根据音频用途做卡状态／可用文件列表、无卡及不支持格式反馈；是否需要独立存储设置由用途决定，不先做通用文件管理器 | 为本地音乐或录音提供有容量上限、格式校验和明确关闭语义的文件I/O。缺卡、满卡、损坏与中断不能阻塞UI；不得把TF故障扩大为偏好／闹钟FlashDB不可用 |
| 音频→提醒／录音／音乐候选 | 先完成下节采购。到手后分开证明短时输出可听且可停止、MIC录得的有限缓冲随声音变化，再做短录回放；先用内部小样本验证基础通路，TF作为后续文件输入。关闭／取消／超时释放PA及音频责任，检查关亮屏共享路径 | 按选定的首个功能更新“声音与振动”或录音／播放页：必要的音量／试听或开始／停止／进度／失败反馈；提醒和媒体不要混成一页。页面范围及音乐音源在功能轮前确定 | 首次仅接一种业务，再独立扩展。提醒须明确静音／勿扰、闹钟／倒计时独立声音规则和多提醒仲裁；录音须有时长／容量／离页规则；音乐先确认本地文件或其他来源。暂停／抢占／恢复与息屏继续各有契约，不默认新增后台录音或远程音乐能力 |
| KEY2／RGB配套 | KEY2记录真实按下／松开，先不赋快捷动作；RGB先明确LDO3共享责任，再限时低亮点亮／停止，保留电机关闭前提 | 有明确用途后，复用按键设置／必要的指示灯设置，不为两个器件各建演示应用 | 候选为KEY2快捷操作、RGB短暂状态提示；具体映射、优先级及息屏行为由功能轮确认。默认不常亮、不新增长期轮询，不改变现有KEY1及提醒语义 |

三个闭环可以复用同一驱动与快照接口，但验收结论分开。页面阶段不启用尚未接通的Product业务；真实数据不可用时如实表达，主机／UI Demo可展示设计样例。硬件轮的串口诊断入口不永久混进用户界面。

## 喇叭采购准备先行

2026-10-23读取的[立创官方硬件页](https://wiki.lckfb.com/zh-hans/hspi-sf32lb52/hardware/board.html)列“外接GH-1.25mm接口的3W/4欧或2W/8欧喇叭”；音频接口节列“最大支持3W/4欧姆”及“GH-1.25mm母座”。它们是板卡适配候选，不是本机在任意供电下都达到额定功率的测量。

采购准备交付物为：至少一个实际SKU／规格页，阻抗与额定功率、外形尺寸、接口配对／针数／线序、是否附线、数量及含运总价；结合实物板修订／接口核对后再选订单。先满足开发板有声验证，不在此轮承诺最终手表体积。保留500元原预算，历史余款不当作最新余额；不买重复模块，不由规划记录自动下单或联系卖家。已有TF卡只需核规格和数据保护，不再采购卡。

## 共用资源与验收方法

- **I2C3／传感器电源**：`product_imu_diag.c:413–428`已配置PA39／40、PA30、100kHz／50ms。LTR、MMC与IMU必须协调总线配置／事务与电源，退出单器件不能断共享电源；优先扩展现有所有者或最小串行接口，不新建通用资源框架。SDK错误路径含RT_ASSERT时，在项目适配边界明确失败／超时／停止，不改锁定厂商树或用UI线程执行阻塞I/O。
- **LCD／音频PA**：`bsp_lcd_tp.c:36,51,75–76`关屏拉低／改PA42，开屏再拉高；Product充电总线借用路径`product_charger_bus.c:69–79`仍关闭PA42。息屏声音或录放音前必须明确PA42的所有权与恢复，不能仅添加音频API。TF启用也要核对PA26／3.3V及LCD电源分支，不沿用只亮屏时可读的结论。
- **硬件能力优先**：遵循[硬件能力门槛](HARDWARE-CAPABILITIES.md)，先核精确芯片内置配置／自检等能力。单位换算与产品亮度映射可以在项目层实现；不得把驱动缺陷当硬件算法不足，更不能无对比实验重写已有硬件算法。
- **最小必要验证**：硬件轮集中一次操作窗口，合并“识别／输入输出变化／停止恢复／受影响共存”检查；只有失败或新改动才补测。不重复A0／A1整套、完整主机61项或无关佩戴测试。软件运行相关目标及Product构建；共享UI变化再验证Demo及官方输出。功耗／SOC／长期可靠性独立收证，不作为普通页面轮的统一前置条件。
- **停止边界**：总线异常、停止未确认、原有计步／腕出现新增故障，先收束该路径并保存版本／原始证据；不边故障边加页面。每轮记录源码检查、编译与同BIN设备结果，按CONTRIBUTING独立PR交付；设备操作到执行轮重新核当前条件，不沿用本规划授权。

## 建议的首个执行闭环

先做 **LTR-303硬件跑通准备**：精确资料／寄存器与单位核对→最小限时诊断及共享I2C3协调→相关测试／Product编译→获准后一次集中读数与停止恢复。该轮不开放自动亮度、不制作新页面、不调整AOD亮度。并行的喇叭工作只到匹配候选和完整报价；其余轮次是依赖顺序，不是本次自动执行授权。
