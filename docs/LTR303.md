# LTR-303 双通道硬件跑通

本轮是[板载资源三步顺序](BOARD-RESOURCES.md)的第一步：先限时硬件读数与停止恢复，再做亮度页面和自动亮度。活动项与唯一下一步见[STATUS](STATUS.md#current)。本轮不改页面、亮度策略、AOD或用户偏好，不以原始计数冒充lux。

**24日后续功能轮**：[真实自动亮度](PRODUCT-SETTINGS.md#automatic-brightness-20261024)复用同一状态机新增显式continuous入口，固定配置／锁存／有效性／恢复路径不变，没有第二个驱动或滚动诊断。原`wf_light start`仍限1–120秒，只有Product模式与显示资格共同放行时才持续采样；暂停／故障释放、故障重试、单位换算与校准边界由该节统一定义。下文“默认无采样／未实现换算”描述原诊断／页面轮版本，不能作为当前功能轮状态。

## 精确资料与能力选择

板卡资料列LTR-303ALS-01，锁定SDK传感器示例使用I2C3／PA39、PA40／地址0x29。现有SDK的`LTR303_ReadVisible()`只返回CH1，而包装器标`RT_SENSOR_UNIT_LUX`；因此本轮在项目适配层明确读双通道和有效性，不直接采用该单位标签，不修改厂商树／SDK锁。原生ALS测量、增益、积分和重复周期仍由器件完成，没有软件替代其测量算法。

已读取[Adafruit下载页](https://learn.adafruit.com/adafruit-ltr-329-ltr-303/downloads)链接的[Lite-On原厂手册](https://cdn-learn.adafruit.com/assets/assets/000/115/506/original/LTR-303ALS-01_DS_V1.pdf?1664491385)，封面LTR-303ALS-01／DS86-2013-0004／Rev A／07/09/2014。下列是印刷页码，PDF页码加1：

| 项目 | 手册依据与本轮使用 |
|---|---|
| 身份 | p12／16，7位地址0x29，PART_ID0x86为A0，MANUFAC_ID0x87为05；不匹配只报告，不写配置 |
| 控制 | p14，ALS_CONTR0x80 bit0为active、bit1为自清reset，bits4:2增益；本轮写01：1×／active，不发reset |
| 周期 | p15，MEAS_RATE0x85显式写03：100ms积分、500ms重复。p13与p15的默认值不一致，不依赖复位默认；重复周期编码5／6／7均为2000ms，旧合法值允许保存恢复 |
| 启动 | p5–6，供电后≥100ms再active；active后≥10ms唤醒再积分。本轮在配置前等100ms，激活后至少200ms才开始看STATUS，实际NEW位仍为数据就绪依据 |
| 数据 | p17–18，严格88→89→8A→8B，CH1低高／CH0低高；首次读锁住同帧，8B释放。四次单字节读采用手册顺序，部分失败仍尝试末寄存器释放锁 |
| 有效性 | p19／26，STATUS0x8C bit2=NEW、bit7=INVALID、bits6:4为增益。本轮只接受NEW且INVALID=0、增益000；任何通道FFFF按满量程保守标饱和，不保证INVALID覆盖所有饱和 |

## 实现与命令契约

`ltr303_diag.c/h`拥有纯状态机，`product_imu_diag.c`沿用现有唯一传感器worker执行所有I2C3配置与事务。FinSH只预约／取消并打印同步缓存，不执行硬件I/O；无新线程、timer、IRQ、持久记录或开机采样。

```text
wf_light status
wf_light start 30   # 显式1..120秒；示例不是设备操作授权
wf_light stop
```

重复start不续时。仅日常计步正常、共享所有者无已知故障时可开始；有限腕诊断与本诊断双向互斥，既有IRQ驱动常驻翻腕偏好仍可共存。先等待并核身份／原配置，已active／reset或保留位不支持则拒绝，不抢占未知ALS使用者；进入固定配置前清旧数据，写后读回确认。

每个会话有编号／原截止，约每秒读取一次；报告NEW、INVALID、增益、通道值、饱和、采样时间／年龄及计数。没有NEW时不捏造新样本。截止包含总线准备和配置耗时，读取前及返回后重查取消／到期，迟到数据不接受。同步I2C或Flash调用不可被逻辑截止中断，软件时间上限不是物理I/O硬截止。

到期、显式stop、全局日常stop/retry及已知共享服务故障时停止；恢复完整原CONTR／RATE并读回，不拉低PA30、不重置计步、不取消常驻腕偏好。失败写入也承担恢复责任，DATA末字节读失败保留释放锁责任。未确认清理时保持owned和原PM IDLE，禁止新诊断、等待显式stop重试，不自动循环I/O；独立LTR故障不伪造为IMU寄存器已坏。

显式诊断运行期间暂持IDLE、缩短同worker等待至下次观测／截止；现有循环也会更频繁观察计步和腕状态，停止后回原亮屏1秒／息屏60秒等待。它是限时硬件验证负载，不是自动亮度后台调度或低功耗方案。
