## 行为与结构

- `core/component_layout.*` 保存 1–6 页、四个固定模板、应用 ID、独立实例 ID、尺寸、两种配色。默认三页由此统一提供，不以 XML 样例决定运行中页数。重复应用合法，重复实例 ID 和不完整正式页面不合法；序列化不写入原始 C 结构体或指针。
- Product 由 `screen_component_page`、既有 quarter/half 和独立 `product_metric_full` 组合，继续使用 165×174、342×174、342×362。活动/天气提供 half/full，其余八种默认组件为 quarter。两色共用同一数据源和入口；未接入能力继续显示 `--`/原因，电量为 USB。
- 按住组件 700 ms 进入当前页编辑，累计移动超过 10 px 取消。编辑页不能横向翻页；普通拖动不会转为槽位点击。点击槽位进入同尺寸纵向选择器，直接选颜色返回。已有槽位替换即发出保存请求，返回编辑；退出不再确认保存。
- 左右 `+` 先选模板，新页未填满时勾选禁用，填满仍只是草稿；点勾才插入正式环并选中新页。未提交退出/KEY1 通过一次 √/× 放弃确认；从组件选择页返回仍保留编辑草稿。整页删除仅一次确认，删除后优先前一组件页；一页不能删，六页不能新增，所有禁用操作整体变暗。KEY1 长按没有电源副作用。
- 编辑器、选择器、模板页沿用页面栈和动画后清理；改布局时重建隐藏的主页环，统一更新点数和选中页。模板/组件页面几何来自官方生成 C，状态和事件逻辑放在 `ui/runtime/components.c` / `ui_shell.c`。

## 持久化边界

独立 `layout_a` / `layout_b` KV 与原 `preferences` 共用已存在的 FlashDB `settings` 分区，不改分区或 SDK。每个记录 512 B：魔数 WFLY、版本 1、页数、32 位代次、固定容量槽位及 FNV-1a 校验。启动读取两份，选择代次较新的完整有效记录；无有效记录则恢复默认三页，产品还按注册表过滤不支持的应用/尺寸。

UI 选择/确认时立即复制完整布局并取得请求 ID，不沿用亮度 1.5 s 空闲策略。既有存储线程每 100 ms 收取最新请求，锁仅保护内存副本；Flash 写入与读回在 UI 锁外执行，始终写非活动记录，完全读回一致后才报告完成并切换活动记录。连续快速编辑可合并为最新完整布局；写入中的旧请求不会将更新请求标为完成。存储失败保留旧完整记录，至少 5 s 后重试；编辑页显示“保存中/已保存/保存失败，稍后重试”，失败另有全局提示。新页草稿不显示上一次修改的“已保存”。无后台存储或线程启动失败时不会伪报成功。

存储线程栈由 4096 调至 6144 B，以容纳布局副本和两份校验缓冲区；具体板端栈峰值仍需测量。日志 `[product] layout saved request=... generation=... pages=... write_ms=...` 只在写入并读回通过后输出；本轮没有板端写入延迟数据。`write_ms` 不含请求排队时间。写入完成前断电可能丢失最近修改，之前完整布局的硬件恢复保证仍需 FlashDB GC/擦除与断电试验，不能把内存后端的测试扩大为物理掉电证明。
