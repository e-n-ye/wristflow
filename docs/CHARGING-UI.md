# 充电画面

用户决定见[BASELINE](BASELINE.md#charging-ui-20261017)，活动项只维护于[STATUS](STATUS.md#current)。参考图是布局及百分比环语义依据，不是本机电量或续航测量。

## 范围与交互

- 390×450黑底，圆角矩形边框、顶部青绿色闪电、中央真实24小时时间和充电状态；未校时为`--:--`。本轮没有SOC，暗色完整轮廓表示进度未知；芯片报告FULL才全环青绿色。没有循环流光、模拟进度或假百分比，XML中的21:10仅为编辑器样例。
- 每次自动充电首次确认ACTIVE时请求展示一次，包含启动时已接USB；只有确认PG=0后下一次PG=1资格启充才是新周期。150ms合并窗口内从未观测到PG0的快速拔插无法与状态中断区分，不承诺重弹。手动诊断start不创建展示周期。
- 正常亮度下任意新触摸或短按KEY1消费本次输入并退出，保留原页面与草稿，不调用停充。插入时已按住的接触须先释放；DIM首次输入只提亮，OFF按键先唤醒；同周期不重弹。充电画面活动期间原页受覆盖，长睡也不在底下清导航；退出后恢复普通策略。
- 沿用现有超时／用户常亮偏好；画面本身无定时动画或亮屏lease，息屏停止LVGL回调。FULL、故障、未知更新已有画面，不触发新展示或唤屏；确认拔出关闭画面。表盘和现有电源信息页仍可查看当前缓存状态。
- 闹钟／倒计时提醒优先；通知提示暂时覆盖充电画面，主动打开消息退出充电画面并沿用原会话确认。被提醒／提示／页面过渡暂缓的首次展示由Product亮屏250ms协调点用最新快照重试；不在解除覆盖时用旧快照抢屏。

## 所有权与接线

`product_charger_service`在原有IRQ同步缓存中发布非零`charge_cycle`：同一自动尝试仅首次可靠ACTIVE设置，确认PG0清零；status INT不分配。发布缓存后才发`WF_EVENT_CHARGER`，邮箱位只作重读提示，事件合并不能重新播放旧周期。UI持有已接受的cycle，退出不重置；getter只复制／映射，无I/O。

Product息屏等待在LVGL timer停止时重读缓存并协调覆盖层，仅新展示返回true才需要亮屏。FULL／故障事件仍在息屏中更新，不直接退出等待。首帧完成后提亮的原顺序保留；充电控制、共享I2C供电保护和参数不由页面改变。

视觉源为`ui/xml/components/charging_panel.xml`，经官方Pro GUI导出；手写`charging_view.c`只绑定真实缓存、显隐与一次展示。shell协调输入、提醒、草稿和呼吸暂停／恢复；不新增全局导航枚举或设置存储。百分比进度长度留待可靠SOC另轮接入。
