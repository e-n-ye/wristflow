# WristFlow 产品设计记录

更新：2026-09-24。状态：设计访谈进行中；下方分别记录用户已确认的方向、图片观察、工程建议和未决问题。本记录不代表视觉验收、固件实现或功耗验证通过。

## 本轮确认

- Redmi Watch 4 继续作为操作与视觉参照；应用入口采用官方 Watch 的蜂窝菜单方向。用户接受其余已纳入范围的页面接近 Redmi Watch 4 的设计，不再把全系统黑白作为硬性要求。这不扩展首版功能范围。
- 保留大号小时数字的造型方向，重点修正当前蓝色与机械分割感，追求参考表盘中央实体、两侧分层且有毛玻璃感的扩散效果。用户随后明确：Redmi Watch 4 肉眼为白灰，中间比较白，旁边两层是带毛玻璃感的灰色；偏蓝来自拍摄。因此撤销淡冰蓝候选，样稿只使用中性白灰。
- 第二轮样稿反馈明确：不要倾斜的侧片。扩散的视觉关系是完整原始小时数字上覆盖两侧的毛玻璃；`10`、`11`、`12` 应按整组处理，两字之间保持正常字形和字距，不对每个数字分别向中间扩散。
- 每侧毛玻璃宽度按外层 : 内层约 `1 : 2`；靠近白色主体的内层较宽。该比例用于本轮样稿，总覆盖宽度仍由视觉对照调整，不代表所有数字的最终尺寸已验收。
- 动效没有定案。用户认可 Monica 的呈现质量，但尚不能仅凭“开屏动效”这个名称判断是否好看；不能把此前建议的开屏播放、分钟过渡或持续呼吸写成已确认需求。
- 首版打磨一个扩散表盘，该款式没有可配置的信息内容。固定显示信息不等于可编辑组件；本轮未决定删除已有分钟和电量展示。
- 长期支持用户长按主表盘进入表盘选择页。换表盘只替换主表盘页面，不替换应用菜单、核心卡片环、控制中心或整机业务。
- 其他表盘可以提供一定程度的信息配置。扩散表盘没有可编辑信息项，不能为统一界面强制增加空的组件编辑入口。
- 现在需要为以后添加表盘留下适当接口；首版只有一个精修款式，不提前承诺本轮完成选择页、多款表盘或编辑器。

预算、日历、连续试戴、七天续航路线判断、通知/计时/传感器等既定范围见 [基线](BASELINE.md)，本轮没有重新决定这些内容。

| 参考 | 可观察内容 | 设计含义与限制 |

| 图 5 | “扩散”的缩略预览、邻近款式与选中轮廓；照片中未见编辑按钮 | 结合用户说明，扩散款式不提供信息配置；不能仅凭一张照片推断全部页面行为 |
| 图 6 至 8 | 另一款式有编辑入口；编辑内分“样式”和“组件” | 外观选项与信息内容是不同概念，编辑能力由款式提供 |
| 图 9 至 10 | 组件区域被突出显示，内容选择列表包含卡路里、压力、心率等 | 借鉴配置关系，不把参考照片中的每种指标都加入 WristFlow 首版 |
| 后补同框照片 | Watch 4 显示数字 7，黄山派显示旧版数字 10 | 结合用户肉眼说明，目标是白色主体与两层灰色侧片的材质、明暗层次，不照搬照片的蓝偏色 |

“毛玻璃感”在本轮指视觉目标：完整原始数字为底，中央实体笔画清楚，整组数字左右两端各覆盖两层柔和、半透明的灰色区域。它不等于已经选择实时背景模糊算法，也不意味着把整个数字模糊处理。照片中的透视倾斜、反光、摩尔纹和拍摄噪声不能直接当作目标形态或纹理；照片色值不能替代屏幕配色校准。

当前图片来自 [Generate-Ui-Assets.py](../scripts/Generate-Ui-Assets.py) 第 43 至 68 行：Montserrat Bold 数字蒙版、五种固定青蓝色、等宽矩形色带和黑色间隙。该算法解释了当前硬边与纯色分片，不能通过只换蓝色色号得到用户描述的层片质感。

## 最小扩展边界建议

以下是待评审的工程建议，不是已实现的 API，也不替换 [交互契约](UI-INTERACTION.md) 中视觉与产品逻辑分离的决定。确切函数、数据结构和存储格式留到首条运行路径需要时定义。

| 现在值得保留的边界 | 要解决的具体问题 |
|---|---|
| 每款表盘独立管理页面创建、更新、可见状态与销毁 | 更换款式时，不修改全局导航；隐藏或销毁后停止该页面自己的动画与刷新 |
| 从外部取得时间、电量及后续有效数据 | 换表盘不重置时间、计时器、通知或测量任务；显示组件不自行启动硬件采样 |
| 用稳定的款式标识选择表盘 | 添加第二款表盘时不依赖其显示名称或资源数组下标作为持久标识 |
| 样式与组件配置属于对应款式，编辑能力可选 | 扩散可以没有编辑器；其他款式按各自允许的区域配置内容，不套用信息环的固定尺寸槽位 |
| 预览与正式应用区分 | 将来浏览缩略预览时不改写当前款式，也不为每张预览启动后台任务；配置确认/取消和保存时机届时单独定义 |

当前 [watchface_presenter.h](../ui/xml/watchface_presenter.h) 只提供时间更新，不读取 RTC；实现依赖 `hour_artwork`、`minute_label` 和 12 张小时图片。将这些细节留在扩散款式内部，即可逐步形成上述边界；不要求一次实现通用插件、动态安装包或完整配置框架。

官方 Watch 现有构建选择 LVGL 8，自有 UI Demo 配置选择 LVGL 9，编辑器与 SDK 使用 9.4.0。蜂窝还依赖坐标变换和官方应用框架，不能把“菜单真机可用”解释成与现有 UI 直接兼容。版本整合属于后续有界实验，本轮没有选定移植路线。

## 下一份可见成果

3. 静态可接受后，再提供两段可重播的运动草稿，例如“由紧到松展开”和“展开后轻收束”。这些只是样稿候选，不代表已选定触发时机；动画不得妨碍立即读时。
4. 视觉实验通过后，再用黄山派检查实际显示、局部刷新、内存、动画中断及亮灭屏。新增构建结果、用户观察和功耗分别记录。
