# 电压估算电量

本轮授权为[共识](BASELINE.md#battery-estimate-20261018)中的首版估算百分比及现有页面／充电环接入。活动状态和唯一下一步只维护于[STATUS](STATUS.md#current)。本页保存算法、来源与验收契约，不创建第二份队列。

## 数据来源与精度边界

沿用固定SDK `421126d9f476ed8e2a6f0b0ca28a9f241c182e65` 的黄山派 `customer/boards/sf32lb52-lchspi-ulp_base/battery_table.c` 充放电表，每5%取一个参考点，共21点／表；相邻点线性插值。表中41808对应4.1808V，保留0.1mV尺度：同SDK `docs/source/en/middleware/battery_calculator.md` 的示例明确写`38000 // 3.8V`，并将`bat1`通道7读数原样传入计算器。结构／函数注释中的mV与示例数值不一致，不能按普通mV直接使用。

来源可在[锁定SDK算法](https://github.com/OpenSiFli/SiFli-SDK/blob/421126d9f476ed8e2a6f0b0ca28a9f241c182e65/middleware/battery/battery_calculator.c)及[同板参考表](https://github.com/OpenSiFli/SiFli-SDK/blob/421126d9f476ed8e2a6f0b0ca28a9f241c182e65/customer/boards/sf32lb52-lchspi-ulp_base/battery_table.c)复核。只提取参考数据，项目独立实现纯C估算；不启用调用`rt_charge_get_status()`的SDK计算器或其充电服务。旧F411的[复用记录](F411-REUSE.md)主要涉及MAX30102，没有可确认的本电池SOC曲线。

这些点没有电芯型号、容量、温度或负载校准信息，不是原ZCLP500的测量结果；每5%抽样也不同于原101点表。当前无连续电池净电流／电芯温度输入，不能声称库仑计量、容量学习或准确剩余续航。查表、ADC电压对照和SOC曲线校准是不同证据。[TI SLUAAA1](https://www.ti.com/lit/an/sluaaa1/sluaaa1.pdf)说明电压查表需电池特性数据，负载、老化、温度和电压回弹影响结果。

其他对照实现：[Zephyr battery_level_pptt](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/boards/nordic/battery/src/battery.c)将曲线与ADC采样分开并插值；[Bangle.js](https://github.com/espruino/Espruino/blob/master/libs/banglejs/jswrap_bangle.c#L2971-L3015)使用轻量分段电压映射及部分型号的满电电压校准。它们仅供实现比较，本轮不采用其板级阈值。

## 采样与估算契约

- 原power worker每次有效ADC完成分配一个非零`voltage_sequence`和单调毫秒完成时间。先发布电压、后发布PG时复用同一身份；原IRQ短临界区复制、息屏清缓存和epoch迟到拒绝保留。
- UI线程在`main::read_snapshot()`合并charger缓存后调用`core/battery_estimate`；同一sequence只处理一次。首次／可信模式变化后的新样本直接播种，其后IIR为旧值3份＋新值1份；百分比2点滞回，0／99端点和FULL明确处理。没有随时间增加电量、循环动画或息屏采样。
- 电压读取失败、sequence缺失、年龄超过15000ms、节点电压不在3000–4250mV时估算无效；过期同时撤销显示用电压有效性，历史清零。15000ms边界有效，15001ms失效。范围仅为估算输入合理性门槛，不是电池在位检测、放电截止或充电保护参数。
- ACTIVE使用充电参考表；可信IDLE／STOPPED使用放电参考表。UNKNOWN／FAULT或独立PG尚未返回的普通模式不猜曲线、不消费新sequence；恢复可消费该样本。普通模式切换复用旧sequence时先显示未知，等新ADC；FULL可在仍有效的样本上锚定100。
- 所有电压查表结果最多99；只有现有charger逻辑报告FULL且ADC样本有效时输出100。显示仍是估算，FULL文字／软件状态不证明物理停流。0%仅为参考表低端，不触发任何新关机或停充动作。
- estimator与显示不改充电参数、启停、故障处理、原插接周期、提醒优先级、退出消费或PM策略。没有新增timer、worker、电源lease、Flash保存或设备I/O。

## 统一显示与进度环

`power.estimate_valid/estimated_percent`进入共同快照及`power_equal()`，`wristflow_product_apply_power()`同步legacy电量字段，防止有效性／数值不同步和刷新遗漏。共用formatter显示`~59%`，未知回退有效电压或`--`；UI Demo原确定性百分比不加`~`。

表盘、卡片、设置与关于页复用同一formatter；表盘有效百分比保留显示，以颜色辅助表达充电／故障。现有电量页同时显示估算、实测节点电压、USB和充电状态，并写明“电压估算”；有效性变更后继续刷新，不因percent可用退回占位页。没有实现新的电池设置／长续航／续航优化页。

10-18后续[正式电池主页面](BATTERY-PAGE.md)覆盖上段“没有新电池页”的阶段限制；现有SYSTEM路由改用官方XML新布局，未知大号电量为`--%`、电压独立显示。算法及下文原BIN证据不变，新布局的验证另见页面契约。

充电XML声明百分比和提示控件，官方Pro GUI导出；手写适配层对既有圆角轮廓按路径长度绘制比例，顶部中点顺时针，未知保持暗环，有效FULL估算才全环青绿。样本失效时数字和环一起回到未知，charger缓存的“已充满”文字仍独立保留。仅数值／状态／时间变化时更新；不会建立新插接周期或重新弹屏。XML的`~59%`只是编辑器样例，真正绘制使用同一Product估算。

## 2026-10-21 手电筒负载与电量回升：审查及实验契约

用户报告手电筒使用后估算下降、退出后回升，十几分钟白屏与跨夜下降程度差异大，要求设计可靠实验后改进。检查基线为`cff76ed`；这是用户现象与源码审查，尚无本轮同步电压、净电流或设备日志，不认定实物根因。万用表／钳表可借，型号、量程、分辨率和带宽未给出；无测量转接板／转接线，不安排串表拆线。钳表可借不等于能够测准本板低电流。

**同日后续前提修订**：用户授权继续B1并明确ADC数字已测试准确。当前排查采用这项用户已有测试结论，不重复要求借表测准ADC；测试仪器／数值／版本未提供，不能记录为本轮独立实测。下列源码审查保留当时认识，后续重点收敛到映射、负载／恢复和滤波；ADC复查仅在出现相冲突证据时恢复。ADC电压准确不能证明剩余容量百分比或净耗电准确。

### 已核实的软件事实

- `ui/runtime/apps.c`进入手电筒请求亮度100；`core/display_policy.c`使其持续全亮；`product_pm.c`亮屏持IDLE。与普通息屏跨夜不是等负载条件，也没有电流证据。
- `core/battery_estimate.c`的放电参考表未经本ZCLP500校准，现有整数插值把4000mV映射为71%、4040mV映射为91%。这是同一纯函数的计算示例，不是本电池SOC或测得的40mV压降；足以说明小电压变化会被曲线放大。
- `main::read_snapshot()`亮屏约每5秒请求一次原异步采样；estimator按sequence去重，IIR旧3新1、2点滞回，允许上升和下降。退出后的最初显示可能包含高负载样本及滤波历史。
- `product_power_service.c`关屏清缓存并拒绝旧epoch结果；无效／过期样本使estimator清历史，醒来新有效样本重新播种。跨夜前后不是连续滤波下的容量记录，不能按两个百分比相减判断夜间耗电。
- 单位链已查：SDK ADC输出0.1mV并应用VBAT因子，`product_power.c`转换为mV，estimator乘10回参考表尺度；未发现重复分压或单位倍数错误。ACTIVE／IDLE等曲线选择、FULL有效性和UI同步未发现可直接确定的软件缺陷；ADC实际校准、供电压降及电芯特性仍未知。
- 电池页电压显示到0.01V，现有日志虽有mV，但缺少完整样本身份／滤波／重播种信息，且仅值变化时打印。仅拍页面不能重建此次变化。

**待验证假设**：高负载降低节点电压、退出后回弹，陡峭参考曲线与滤波进一步影响估算；检查实际充电状态切换及睡醒重播种。ADC准确沿用上述用户测试，不列为本轮优先疑点。现有事实支持排查顺序，不证明电池内阻、真实SOC或实际DEEP。

### B1：先补可回读的有界诊断

只在现有UI估算入口复制数据，不增加ADC读取、正常采样、息屏定时唤醒、Flash写入或电源申请；不修改曲线、充电控制和页面行为。记录必须显式启动、有限时限／容量并可停止；默认不采集。BAT-only测试先留RAM记录，窗口停止后再导出，避免持续串口／USB充电改变实验条件。实现时核对内存预算和导出同步，不从FinSH直接读取LVGL或未同步的estimator。

必要字段：本次源码／BIN身份、会话与单调时间、页面及手电筒进入／退出、实际显示亮度与ACTIVE／DIM／OFF、USB有效性与charger模式、ADC原始mV／sequence／sampled_ms／年龄、滤波0.1mV、采用曲线、候选及最终百分比、有效性、重播种／拒绝原因。必须区分新ADC、同sequence状态补全及显示事件；滤波无效时不把残值标成有效。记录ADC与估算实际发生时间，不能用回读时刻代替；无息屏采样的区间明确缺失，不补曲线。

软件完成线：覆盖边界／容量／超时与显式停止、sequence去重、重播种／模式未知／过期及导出并发；相关主机测试、Product官方编译及最终产物核对。诊断关闭无额外后台活动；设备是否保留记录、串口是否扰动及真实电压仍另验。活动项只回STATUS，不由本契约启动实验。

### B2：一次集中负载／恢复窗口

1. 操作前重核精确BIN、同板／原电池、实际供电及松线条件。设定记录时限，固定普通亮度、BLE／腕开关、时间、环境和已有显示设置；在开始BAT-only窗口前完成准备，期间不插拔USB、不复位、不手动启停充电。USB同接样本单列，不能作为无充电BAT对照。
2. 普通页面先记录约60秒，进入手电筒60–120秒后退出，继续记录至少120秒；标记退出即时及约5／15／30／60／120秒的样本。首次无需十几分钟白屏，不以低百分比为继续放电目标；异常供电／重启／故障或用户要求停止即结束。
3. 做同等时长普通黑底页面对照，固定正常亮度，逐段记录实际DIM／OFF／亮屏时长与恢复间隔。若两组显示时长不同，只分析各自输入／滤波及恢复，不宣称等负载耗电比较；需要隔离亮度因素时再用相同既有持续亮屏设置组成专门对照。首组整体约10–15分钟；有明确缺证据才补一组，不自动扩成长测。
4. 窗口结束先停止记录，再接回USB导出。保留重连／充电模式改变及其时间；若开口导致重启／RAM丢失，该组无完整证据，记录失败，不拼接为同一窗口。集中安排必要KEY1操作，日志读取不重复要求用户做功能验收。
5. ADC电压准确已有用户测试，本轮不再以表测对照作为前置。后续若新增冲突证据才复核测点与ADC；本电芯SOC／净电量校准仍独立。无转接件时不拆BAT串电流表；测电流／积分能量前另核连接和仪器能力，不能由现有百分比变化反推能量。

| 观察结果 | 后续有界动作 |
|---|---|
| 表测与ADC同向下降／恢复，映射能解释百分比 | 优先评估负载／恢复状态的估算置信度及本电芯曲线；不能把平滑百分比当准确SOC |
| 表测稳定但ADC偏差／跳变显著超出仪器与时间误差 | 先查ADC校准、测点／共享供电与采样条件，再谈显示滤波 |
| ADC稳定，估算跳变与mode／重播种一致 | 定向复现模式／有效性策略，比较修改前后；保留无充电时电压回弹的真实数据 |
| 序列／时间缺失、重启或USB切换污染关键窗口 | 先修采集，不能据缺失记录定SOC修正常量 |

不以强制“放电时百分比只能下降”作为首轮修复；它可能隐藏测量或曲线问题。容量标定／库仑积分及外置电量计属于取得数据后的方案选择，暂不新增硬件或替代算法。真正电量准确度和续航仍需独立证据。

## B1 诊断实现（2026-10-21）

基于`cd3f4aa`，`core/battery_estimate`提供可选诊断副本，原估算接口保留；曲线、IIR、滞回、FULL、去重及无效性规则不改。诊断decision为NEW_SAMPLE0／SEED1／MODE_SEED2／CACHED3／NO_SEQUENCE4／STALE5／NO_VOLTAGE6／RANGE7／MODE_UNKNOWN8／MODE_WAIT9；mode为放电0／充电1／FULL2／未知255。candidate是按滤波电压得到并封顶99的参考值，FULL最终仍可100；无有效滤波时filter／candidate清零且valid=0，不能使用其残值。

Product `battery_trace.c/h`持有256条RAM记录与纯状态机，`product_battery_trace.c/h`持有短IRQ临界区及FinSH导出。UI线程复制当前电源／估算，另观察页面和显示状态变化；不读硬件、不新增线程／timer／Flash／PM请求。未启动时不存记录；同一ADC身份的纯轮询不重复入列，同身份PG补全、模式／有效性变化及页面／亮度变化仍记录。缓冲满即停止，不覆盖首段；新会话显式start才清记录数量，旧数据会被替代，需先导出。

记录区分ADC完成`adc`、估算`eval`及上下文观察`obs`三种单调毫秒时间。`age`为eval−adc，仅非零seq有意义；上下文变化可携带更早一次估算，不冒充新ADC。raw_valid保留估算前ADC有效位，display_valid是过期处理后的显示电压有效性；USB两个数字为有效／PG，非电池在位。surface／phase来自UI拥有者；亮度requested是平台回调最近请求，ack是最近一次驱动SET_BRIGHTNESS成功的值，均非实测亮度／PWM。flags位为UI有效1、ack已知2、LCD上电命令成功4、亮度延后8、充电覆盖16、提醒覆盖32；LCD关闭时不能把旧ack当作屏幕仍亮。

命令只操作RAM或打印同步副本：

```text
wf_battery start 900
wf_battery status
wf_battery stop
```
