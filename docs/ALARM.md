## 已确认的产品契约

- 最多 5 个闹钟，初始列表为空，支持新增、修改时间 / 重复规则、启停和删除。满 5 条隐藏加号，显示“最多只能设置5个闹钟”；删除后不足 5 条恢复加号。等待校时与上限提示接在最后一条闹钟下面，分行显示并随列表滚动。
- 24 小时时分滚轮；仅一次、自选周一至周日、每天、工作日（周一至周五）、周末（周六 / 周日）。真正的法定节假日与调休日历后续接入，首版不以“节假日”误标周末。
- 新增流程为“＋ → 时间设置 → 设置 → 勾提交”。子页的勾只确认草稿，最终设置页的勾才提交整条记录；新增提交默认启用，编辑保留原启停状态。点勾前返回放弃当前未提交修改。
- 点击垃圾桶只弹一次删除确认，确认删除，取消返回编辑页。列表开关直接改变已提交记录，不进入编辑草稿。
- 首版提醒只有关闭，贪睡后续补；智能唤醒与独立每条提醒通道配置未纳入。当前振动遵循全局关闭／标准／增强；勿扰下仍提醒，继续沿用现有全局契约。
- 第二轮保存时间、重复规则、启用状态、一次性已安排日期和重复闹钟的最后已响本地日期；重启不恢复待处理提醒队列、不补响错过的日程。

## 第二轮已确认口径

- RTC 存 UTC，首版使用既有固定 UTC+8。新增、重新启用或修改已启用的一次性闹钟，安排在下一次该时分：未来的今天或明天，当前分钟也安排明天；到期自动关闭并保留记录。
- RTC 无效仍允许配置、保存和启用，明确显示“等待校时”；有效后才调度。尚未安排日期的一次性记录在首次有效校时后安排，已保存的日期保留，过期则关闭。
- 手机 / USB 向前校时跨过不补响；一次性过期关闭，重复安排后续日期。重复闹钟保留每条最后已响日期，回拨后跳过该日期及更早日期，超过该日期恢复；修改和重新启用保留进度，删除重建可重新安排。一次性显式重新启用仍重新安排。倒计时继续使用单调时长。
- 当前提醒不抢占，其他按到期先后排队。同刻闹钟先于倒计时，闹钟按创建顺序；每次关闭只处理当前条，最后一条结束才恢复有效原会话及待答确认。通知继续缓存，覆盖期间不弹、不在结束后补播；勿扰仍提醒。
- 每条闹钟最多一条待处理提醒，重复到期合并；倒计时最多一条，含当前条共最多六条。新到期再次亮屏30秒但仍显示队首，之后息屏保留，KEY1唤醒仍可处理；显示活动时限与振动绝对预算分开。第二轮无声音／振动，当前振动扩展以上方2026-10-17契约为准，仍无贪睡或声音。
- 用户新增、修改、启停、删除由后台保存并读回校验，成功才改变有效配置；保存中显示状态，失败保留原配置和草稿并可重试。自动到期关闭与日期进度属于后台状态，提醒交付不等待 Flash；保存失败保留内存进度并重试，重启仍按不补响规则处理过去的日程。
- 第二轮验收限定源码、主机调度 / 存储失败与恢复 / 提醒冲突 / UI 回归及双目标编译、PR 审阅合入；真实 USB、RTC 保时、触摸 / KEY1、息屏到期、精度与功耗留第三轮分别取证。

## 分轮范围

1. XML UI 与独立配置模型：列表、时分编辑、重复编辑、启停、新增 / 删除、草稿与导航；官方 GUI 预览 / 导出、实际 LVGL 主机输入检查及 UI Demo / Product 编译。Demo / 主机开放入口，Product 在调度和保存闭环前阻断入口。
2. Product 调度、持久保存与重启恢复、多个闹钟 / 倒计时 / 通知的提醒冲突处理；日历时间独立于单调持续时长，后台不依赖 LVGL 回调。
3. 绑定同版源 / 三镜像的 USB 真机验收，设备输入、校时、重启、息屏到期和提醒恢复分别取证。

## 第一轮实施边界

- `core/alarm` 只持有配置，无 LVGL、RTOS、时钟、调度、Flash 或堆分配。周掩码的 bit 0 为周一、bit 6 为周日，零表示仅一次；记录有不复用的 ID，列表维持创建顺序，同时间可存在多条不同重复规则。
- XML 持有布局、样式、具名控件与预览样例；官方生成物不手改。UI 适配持有草稿，只在最后确认时提交，离页释放控件但保留本次 Demo 会话的已提交配置。
- 第一轮没有闹钟后台提醒或持久化，无设备操作；演示重入保留不能称作重启恢复通过。

### 第二轮实施与边界

- [alarm_schedule](../core/alarm_schedule.h) 持有日历计划、一次性日期、最后已响日期和每条待处理快照；固定 UTC+8，与倒计时单调时长分开。各闹钟共享 RTC 亚秒到单调时钟的映射，同刻按稳定创建 ID 排序。显式校时修订号触发不补响重算。
- [Product 闹钟服务](../apps/product/src/product_alarm.c) 独占模型、mutex、一次性 RT 软 timer 和保存线程；getter 只复制，息屏不依赖 LVGL。最长五分钟观察一次，保存失败五秒重试；软 timer 争锁时二十毫秒后重试，不等待 Flash 发布锁。RTC 使用 SDK 公开 `GET_TIMEVAL`，亚秒精度尚无设备结论。
- [alarm_store](../core/alarm_store.h) 编码版本 / CRC / 代次及配置日期。FlashDB 两份 payload 加两份 publication marker，共四个 key；先写非活动 payload 并读回，再在版本重查成功后发布 marker。恢复只接受 payload 与 marker 匹配的已发布代次。最终 marker 写入仍串行持有模型锁；物理 NOR 掉电原子性与写入延迟留真机验证。
- 用户操作成功发布后才改变有效配置；准备期间发生到期、校时、ACK 或跨过一次性时分则重新准备候选。自动到期先交付提醒并更新内存进度，后台保存失败显示状态、保留进度并重试；Flash 完成不是亮屏前置。
- [reminder_queue](../core/reminder_queue.h) 持有最多六条纯模型队列；[reminders](../ui/runtime/reminders.c) 在两个 producer 同步前捕获共享单调截止，只收集不晚于该时刻的待处理项，再排序展示。采样期间更新到期的项保留给下一批；移除当前项也等收集完成才推进，避免固定尚未展示的次项。已显示队首固定，其余按截止 / 来源 / 创建顺序排序；宿主只拥有一个覆盖槽，替换不重新捕获会话。业务适配拥有内容并在接受后条件 ACK。
- 闹钟适配保留第一轮草稿与导航，增加等待 / 保存 / 失败状态和五条提醒内容；Product 注入有效后端后开放入口，未注入仍阻断。Demo 继续只做配置交互。
