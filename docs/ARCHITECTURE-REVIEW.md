## 2. 采纳与限定

用户已采纳六项 P0 原则：稳定身份、同步快照、Product 禁用 fixture、后台截止时间与系统唤醒、独立提醒仲裁、配置按槽位降级。P0 表示后续设计/修复优先级，**不表示本轮立即重构**。

| 审查观点 | 处置与理由 |
|---|---|
| 稳定身份，禁止枚举顺序表达类别 | 采纳。具体字符串/整数/生成映射延期；领域元数据隔离 LVGL，UI 描述符可以带工厂/回调，不要求所有描述符纯数据 |
| Product 不含伪造数据与 mock 注入 | 采纳为构建边界。演示和诊断目标独立；不能靠运行时 `product_mode` 证明已裁剪 |
| 线程安全快照 | 采纳。读、写、重置必须共同遵守所有权/同步；通知版本检查也不能引入新的竞态 |
| 截止时间、系统唤醒和提醒仲裁 | 采纳；日历闹钟与单调时长区分。暂停 LVGL 回调不证明 tick 停止，不推翻既有秒表分项实机结果 |
| 缺失模块逐槽降级 | 采纳。保存原引用，保留无关槽位；新默认配置可显式声明，只须与编入模块一致，不必自动推导 |
| 资源全部不能被链接剔除 | 限定为源码依赖风险。Glob 与集中取地址可见；最终留存、内存区域和增量必须看对应配置 map |
| 33 应用 × 两种配色必然越界 | 不采纳该绝对结论。选择器按尺寸/卡片支持过滤；当前 14 个注册项。某一尺寸合格项达到 17 个时，32 槽选项数组才不足 |
| 通知每次必拷贝约 21KB | 不采纳。快照容量约 20.9KB，实际按 `phone.count` 拷贝；版本检查晚于快照调用值得优化，但须量化有效数据量 |
| 为 BLE 序号加原子递增即可解决 | 不足。还要保证分配序号与入队顺序符合接收检查契约；原子计数单独不能证明正确 |
| PM 软件计数证明物理深睡/续航 | 不采纳。计数是软件路径证据；驻留、电源轨电流与能量需独立测量 |
| 只允许“定时唤醒”和“亮屏保持”两种 PM 请求 | 不冻结该限制。硬件活动也可能需要有期限的休眠约束及退出清理，不预建万能资源管理器 |
| LCPU 不可改，所以算法只能在 HCPU | 不采纳后半句。保留已确认的手机算法路线；HCPU 可承载适合当前预算的任务 |
| 统一所有列表、四类页面、六条总线 | 不采纳。优先共享视觉和确实相同的交互，模板/流分类只用于检查；连续样本走专用缓冲 |
| 固定半天工期、10 分钟 ±1 秒作为当前承诺 | 不采纳为已确认预算。后续任务在核对硬件时间源与范围后制定时间箱、误差和资源指标 |
