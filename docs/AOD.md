# AOD 息屏显示

本专题保存目标、面板证据和分轮边界；活动项及唯一下一步只在[STATUS 当前区](STATUS.md#current)。依据[六项任务契约 A0／A1](ARCHITECTURE-REVIEW.md#next-six-20261021)，先验证精确面板路径，再接正式显示状态。Redmi照片只作为外观／交互参考。

## 2026-10-22 已确认目标

用户要求设置→显示与亮度中加入“息屏显示”和“默认息屏样式”。开启前先确认续航影响；抬腕亮屏已开启时，再选择抬腕后的显示目标：“息屏表盘”会关闭抬腕亮屏，“主表盘”保留开启。取消不提交半套设置，不用未经测量的续航数字。

本轮补充确认：首版保留禁用的“智能开启”，说明真实睡眠／离腕来源尚未接入；先做关闭／定时开启。定时页沿用共用选时组件，参考初值08:00–22:00，跨夜与相同起止的具体校验沿用已有定时约定。两种黑底数字布局分别为居中时间／日期、左上时间／日期／估算电量；横向选择、点击应用，首版无“编辑”。正式A1实现前仍须对照本屏A0结果确定亮度和刷新策略。

以上是已确认目标，**本轮A0尚未实现这些设置、保存、样式或AOD产品状态**。当前表盘没有专属AOD样式注册，不提前显示“优先使用表盘自带样式”的能力承诺。长续航保持正常息屏，不能用其极简页代替AOD。

## A0 有界软件诊断

`apps/product/src/aod_panel_probe.c/h`只拥有一次面板借用及恢复状态；`main.c`的UI线程唯一执行LCD I/O。FinSH只预约命令／复制缓存，IRQ临界区内不执行LCD操作。启动默认不实验，不新增worker、timer、采样或常驻刷新。

```text
wf_aod status
wf_aod start 30   # 10..60秒，显式预约；例子不是设备执行授权
wf_aod stop       # 取消；若恢复未确认，则在亮屏窗口显式重试原状态恢复
```

只接受普通模式、ACTIVE、稳定的HOME表盘第0页、无提醒／充电覆盖；执行前重新检查，过渡／滑动、暗屏、息屏或长续航拒绝。开始前等待当前显示提交不忙，最多1秒；进入普通OFF前撤销尚未执行的预约，不把预约延到下次唤醒。重复start不续时、不排队。

UI线程暂停LVGL调度，借用当前正常模式和驱动亮度，先请求5%再启原生Idle，核对SDK缓存；逻辑10–60秒截止包含配置耗时。整个静态窗口不做画面提交，保留当前表盘，便于区分面板自行保帧与主机反复重画。**仍持有正常亮屏的IDLE请求，触摸硬件与其他服务不变**；它不是深睡实验、完整AOD、耗电对照或刷新率测量。SDK内部同步调用可能无限等待／断言，项目期限不能中断已进入的SDK调用，不承诺物理I/O的硬截止。

到期、显式stop、KEY1或任意已有服务事件均结束静态窗口。KEY1本次输入只取消；其他事件位交还正常仲裁，提醒／通知／充电服务仍按其权威状态处理。取消在配置同步调用结束后生效，不宣称中断I/O。恢复始终尝试退出Idle和还原原亮度，重新取得SDK状态／亮度；两条控制返回和本次观察全部符合才标`restored=1`。失败保持FAULT，即使后续清理成功也不把失败改成实验完成；未确认恢复时保留`restore_pending=1`并拒绝新start，继续冻结LVGL和独占LCD，阻止普通绘制／亮度／息屏覆盖原恢复责任。此时事件阻塞等待，只有新发的`wf_aod stop`才重试一次，不自动循环I/O；服务事件累积，确认恢复后再交还。故障期间不能保证画面可用或提醒即时呈现，必须先处理恢复失败，不能继续正常AOD验收。

`status`只读同步缓存，不发LCD控制。phase：0未使用、1运行、2到期完成、3取消、4拒绝、5故障；valid的bit0／1／2分别表示before／entered／after的SDK缓存观察有效。本次恢复观察失败会撤销after有效位，不沿用旧结果；mode：0其他、1正常、2Idle。`restored`不是实测面板恢复，画面与触摸另由设备观察。
