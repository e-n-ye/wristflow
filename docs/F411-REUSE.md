# 旧 MAX30102 代码复用评估

2026-09-21，在 Nano 基础编译通过之后只读检查。未修改、搬运或运行旧项目测试，未验证旧手表当前状态。

范围：`D:/MY_Desk/project/watch/magic_watch_new/products/f411_watch/sensors/watch_max30102.c`、`.h`，以及 `tests/watch_max30102_test.c`。以下为当前这套实现，不代表所有历史 F411 版本。

## 已读到的能力

- 总线通过 `watch_max30102_bus_t` 的 read/write/context 注入（头文件 60～70 行），主逻辑不直接依赖 STM32 HAL 或 RTOS。
- 有身份校验、FIFO 六字节解码、原始 RED/IR 值与简单 `finger_on` 标记；这是原始采样服务，不是已验证的心率算法。
- `service_process` 推进初始化状态机；复位等待有 100ms 超时（源文件 149～165 行）。
- READY 路径有读取节流、FIFO 数据和错误计数。测试使用 fake bus，覆盖身份、FIFO 解码、初始化、无数据、发布失败和复位超时等场景。

## 与新项目范围之间的缺口

- `service_init` 只初始化软件状态；没有电源、IRQ 和低功耗生命周期接口。
- `process` 遇到 FAILED 后持续返回 false（源文件 125～136 行），没有自动最多一次重试策略；外部可重新初始化不等于已有完整恢复流程。
- 没有 stop/cancel/shutdown 接口，不会在测量结束时自动关闭 LED、停中断或释放休眠资源。
- `read_latest`（239～247 行）仅检查 sample_valid，曾经有样本后可继续返回旧值；缺少产品需要的新鲜度、测量结果有效性与失败原因。
- 固定采样配置和原始阈值需要结合模块电气、信号与功耗重新核验。不能把复位超时等同于单次测量任务超时。
- 当前检查未证明板端调用、I2C 适配、真实 IRQ、电源控制或低功耗退出可用。已有 host tests 也不能证明这些硬件行为。

## 主代理判断

保留协议编解码、总线注入方式、初始化步骤和 fake-bus 测试作为复用候选。到传感器阶段再决定提取范围，先补齐测量任务的开始、完成、取消、超时、一次重试、失效和退出路径；不整包迁入旧产品，也不现在重构旧项目。

先在旧 F411/MAX30102 上验证启停与任务策略，再在目标板接入独立模块。F411 整板电流不能代替 Nano 的传感器增量负载。后续新增测试重点是故障退出、旧样本失效、重试上限和资源释放，而不只是再次验证寄存器常量。
