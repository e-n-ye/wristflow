# 页面栈与视图生命周期

日期：2026-09-25。用户在确认触摸修正版“明显改善”后，授权先建立最小页面栈和生命周期，再逐项接入已有规划中的应用。分支 `codex/page-stack-lifecycle` 基于 `8f1cf1b`（PR #15 已通过最新 Firmware / Build baselines 并合入）。本轮沿用已确定的返回、KEY1、菜单位置和后台秒表契约，没有新增待确认的产品选择。

## 行为与边界

`core/watch_core.*` 将单个返回来源改为固定容量导航历史：最多 8 层，包含主页；Back 弹出一层，KEY1 在表盘打开菜单、其余位置清空路径回表盘。主页卡片索引仍单独保存，不把一次横向拖动当作页面入栈。

普通应用现在可以打开另一个应用。路径中同一 surface 只允许一个实例，重复打开、非法目标和超出容量均返回失败且保留原路径。这是当前单实例模型的边界；将来出现同类详情页的多实例需求时，再增加带参数的页面实例。core 仍是纯 C、固定内存，不依赖 LVGL、RT-Thread 或堆分配。

实际可操作的新路径为：控制中心 → 设置 → 点击电量百分比 → 电池占位页。连续返回依次恢复设置、控制中心、表盘；任意深度按 KEY1 直接回表盘。电池内容仍是独立占位页，设置和表盘电量来自演示快照。

## 所有权与释放时点

| 对象 | 所有者 | 保留与释放 |
|---|---|---|
| 主页、卡片、控制中心、表盘实例 | `ui_shell` | 随 shell 保留；表盘仍可独立替换 |
| 蜂窝菜单 | `apps` | 首次进入创建，保留至 shell 销毁，恢复浏览位置 |
| 普通应用、表盘选择页 | `apps` | 按需创建；当前页和栈内父页保留；退出路径后释放 |
| 秒表模型、亮度值、快照 | `apps` / 纯 C 模型 | 独立于应用控件树，释放页面不清除业务状态 |
| 转场收尾定时器 | `ui_shell` | 通常暂停；仅转场收尾使用，shell 销毁时删除 |

去掉了 shell 的第二份应用页面指针缓存。`wristflow_apps_screen` 创建时返回 `created`，shell 只给新页面绑定导航回调；`apps` 是应用控件树的唯一所有者，释放前先将缓存置空。调用者不能在页面退出路径后继续持有其控件指针。

生命周期按以下次序执行：

1. `open` 先尝试更新导航并创建目标；工厂返回空时恢复旧导航。当前 LVGL 分配器的整体内存耗尽仍按 SDK 断言处理，不承诺恢复。
2. `wristflow_apps_activate` 在转场开始前离开旧视图、进入新视图：取消菜单/选择页动画、恢复手电亮度、调整秒表定时器、同步目标显示。保留的选择页父页面恢复原选中位置，新实例从当前使用表盘开始。
3. 转场期间拒绝新的导航请求。`SCREEN_LOADED` 只唤醒一个 1ms LVGL 定时器；它在事件调用栈返回且 `lv_display_get_screen_prev(NULL)` 清空后，调用 `wristflow_apps_collect` 释放不在路径中的普通页面，然后允许下一次导航。
4. 总销毁先停用表盘并删除收尾定时器，再无动画切到空屏、停止应用定时器/动画、释放控件和上下文。返回的活动空屏归调用方或 LVGL 最终反初始化管理。

延后释放有具体源码原因：锁定 SDK 的 `lv_display.c::scr_anim_completed` 在目标 `SCREEN_LOADED` 后仍向旧页发送 `SCREEN_UNLOADED`，最后才清空 `prev_scr`。因此不能在目标加载事件中同步删除旧页。

全部操作仍在同一个 LVGL 线程。新增的收尾定时器不是 RT 线程，平时暂停，没有添加阻塞等待。秒表可见时约 40ms 更新，隐藏且运行时每秒维护 tick、停止绘制，暂停后停止定时器。导航栈解决多级返回与资源归属，不据此宣称 LCD 同步等待、帧率或电流已改善。

栈内父页面仍占内存，最大深度下的真机峰值内存尚未测量；容量上限不是内存预算验证。通知中断、灭屏恢复、配置持久化、服务订阅和通用缓存淘汰留待对应功能接入。
