# 2048 小游戏

本轮来自[用户决定](BASELINE.md#game-2048-20261018)，活动任务与下一步只见[STATUS](STATUS.md#current)。

## 行为与所有权

- Product应用列表／三列菜单提供`game_2048`独立入口，无组件卡片；新增surface追加在旧编号后，不改变既有编号。纯C`core/game_2048.c/h`拥有4×4指数棋盘、得分、最高分、随机状态和胜负；`game_2048_view.c/h`拥有前台绑定与短动效，无硬件I/O、后台线程、持续timer或PM申请。
- 上下左右滑动向对应方向压缩并合并，同一原方块一回合最多合并一次，得分增加合并所得值。开局两个方块；每个有效回合仅生成一个随机空位的2或4，名义概率90%／10%；无效滑动不消耗随机序列、不加分、不生成方块。
- 首次得到2048显示达成提示，可继续挑战或重开；没有空位且不存在相邻可合并方块时结束，可返回或重开。正常局重开先确认，取消保留原局。`uint32_t`得分饱和，达到百万后用整数K缩写；指数上限31不再合并，避免溢出，超过32768的方块用`2^n`表达。
- 视图由apps按导航生命周期回收，棋局模型与本次运行最高分保留在独立view owner，离页重入继续。短睡恢复、长睡回表盘、KEY1、DIM吞首次输入、提醒覆盖均沿用系统；长睡回表盘后仍可重入棋局。设备重启重新开局，不承诺Flash保存。
- 棋盘内四向手势由游戏处理，左边缘起始右滑留给系统返回，页头不落子。新块／合并块130ms轻微缩放，删除视图同时清除所属LVGL动画；不申请持续亮屏。
- `ui/xml/screens/screen_game_2048.xml`和`components/game_tile.xml`拥有390×450黑底暖色布局、具名控件与预览样例，经官方Pro导出；Product实际棋盘来自模型，XML彩色样例不作为运行数据。沿用既有数字／中文／图标资源。
