## 下一步顺序

1. **RTC 复位保时排查**：首轮 USB 产品功能验收已有证据；下一项比较同一 UART 连接下软件复位与 RTS 复位的 RTC/备份域状态，必要时加入只读启动诊断。RTC 校时正常走时与复位保时分开判断，不能用缓存时间掩盖复位丢时。
2. **USB 阶段设备状态与电源**：接通产品模式的变暗、熄屏和 KEY1 唤醒，验证没有电池时的明确状态。逐项上板验证，不把旧固件结果扩大为新固件通过；实物版本、触摸边缘和内存容量继续核对。
3. **BLE 联合固件**：以官方 BLE 和 Bringup 为依据，处理非 BLE 的 LCPU 睡眠假设，接入连接/重连、手机校时、基础通知接收/删除及连接状态。Gadgetbridge 最小实验累计最多 8h，完整兼容后置。
4. **联合验收**：达到基线中的 USB 30–60 分钟、导航/亮灭屏/连接循环标准；电池、电机和佩戴结构到位后再推进电池阶段的测量与试用。
5. **传感器阶段**：按 F411 复用评估补齐测量生命周期，再接 PPG/IMU；UI 流畅度与 BLE/PM 主线不等待计步或睡眠算法。

## 未解决的实施风险

- XML 历史样式/参数/字体问题已修复并真实渲染；Community 不含官方 CLI，仍需人工 GUI 导出及截图复核。CI 编译生成 C 不能证明其与最新 XML 同步。静态 `10:48`、样例数据和 12 张小时图不代表真实 RTC、连接或传感器功能；呼吸/伸缩动画与硬件刷新功耗尚未验证。
- 12 张 342×282 的 RGB565 小时图片未压缩像素数据约 2.21 MiB；历史 `hour_seven_data.c` 已不再由官方 CMake 清单引用，并已从 SCons 图片源收集中排除，避免无引用 ARGB8888 数据继续增加固件体积。
- Hello/BLE 基础例程 PM 关闭，Bringup 已开启 PM 但无 BLE；仍没有同一固件下的 UI/BLE/休眠运行证据。
- 黄山派物理 PSRAM 和默认数据分区均为 8MB；不能沿用 Nano 物理 16MB 的资源预期，应用峰值与板上容量待测。
- 官方例程链接有 RWX LOAD segment 警告；未修改链接脚本，运行风险仍待板端验证。
- Bringup 编译包含官方 LVGL `lv_obj_tree.c:274` 的潜在空指针警告；触摸开关是 SDK 异步操作，快速熄屏/唤醒及驱动定时器释放须重点实测。
- 黄山派实际版本、附件与整机厚度待核实；PPG、电池、电机和固定结构仍需选型。充电参数、电池极性、共享电源和屏幕/音频/充电驱动耦合见复评及验收清单。
- 采购等待计入 2026-09-21 至 2026-12-21 的日历；按每周 20h 规划，十二周评审点为 2026-12-14。
