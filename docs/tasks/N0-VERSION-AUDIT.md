## 5. JSON 证据字段

UTF-8 标准 JSON，不带注释；不存在的值用 `null` 并给原因，不填零 SHA。路径与哈希必须是本次实际读取所得。

| 顶层字段 | 必需内容 |
|---|---|
| `task_id, task_spec_sha256, started_at, finished_at` | 固定任务 ID、任务书原始 SHA-256、带时区时间 |
| `workspace` | 绝对路径、分支、起止 HEAD、开始/结束的原有变更路径与 SHA；不含设置文件正文 |
| `refs` | 每对象 ref/full SHA、获取方式/时间、remote verified 或 local-only/unknown、SDK 锁与 gitlink/checkout 比较 |
| `comparisons` | 四组 A/B SHA、共同祖先、差异文件分类、原始输出路径 |
| `builds` | 每份记录路径/原始 SHA、记录声明、源码计数与每个非原始匹配项、覆盖限制、三镜像路径/大小/期望和实际 SHA/状态 |
| `risk_matrix` | D1/D2/D3/D8 × 三版本；结论、触发条件与 `commit:path:function/line` 证据 |
| `device` | 历史记录列表及来源；`current_device_identity: "unknown_not_observed"` |
| `recommendation` | 推荐基线 SHA、单一目标、理由、文件范围、未来验收条件和未满足前提 |
| `commands` | 证据 ID、工作目录、实际命令/等效工具、退出码或工具状态、原始输出路径；不保存凭据 |
| `gaps, self_check, submission_status` | 缺口/影响/下一动作、A1–A10 自检；状态固定 `awaiting_codex_review` |

核验状态采用 `match / line_ending_only / mismatch / missing / unknown / not_applicable`，并说明应用对象；不得把 missing/unknown 合并成 match。没有原始记录而仅有文档引用时，单列 document-only。本节规定内容而不预建结果，禁止把此表当成已完成的证据。
