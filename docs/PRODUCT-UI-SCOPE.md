更新：2026-09-26。来源为连续 grilling 答复及用户提供的 Redmi Watch 4 设置、组件编辑照片。默认内容以下表为准。[反馈修复](PRODUCT-UI-FEEDBACK.md) 和 [组件编辑保存](COMPONENT-EDITOR.md) 已有用户上板反馈，具体范围见 STATUS；后续 [设置与显示状态](PRODUCT-SETTINGS.md) 已通过本机验证，尚未烧录。以下保留完整目标契约，不把需求确认或主机通过当作硬件验收。

## 阶段目标与范围

黄山派承担可日常操作的产品框架：表盘、组件页、控制中心、应用菜单、应用页面、通知中心和设置。继续在同仓库 `product` 目标中复用 UI；`ui_demo` 保留确定性演示与独立编译，Bringup 保留诊断用途。先打通入口、真实能力状态和保存，再逐项补齐功能。

| 分类 | 当前安排 |
|---|---|
| 现在可做 | 应用/组件注册表、统一路由、组件编辑与保存、表盘管理、手动亮度、熄屏时间、临时持续亮屏、普通熄屏/KEY1 唤醒、秒表、手电筒、USB/设备状态、关于、RTC 状态/校时页面、通知空状态 |
| 有板载资源但尚未接入 | BLE；光感自动亮度；IMU 基础活动/计步及抬腕亮屏。自动亮度先验证光感读数再开放开关，抬腕亮屏先占位 |
| 有实现路径但需要实验 | 低功耗状态下由触摸中断唤醒，验证可行后才开放单击亮屏；不做保持轮询的替代版本 |
| 后续能力/占位 | 心率、天气、睡眠、血氧、声音与振动、真实电池/充电、BLE 通知与勿扰、按键唤 AI、系统操作、熄屏显示及其样式 |
| 明确不做 | 自动运动识别、设备密码，不显示对应设置项 |
| 暂不纳入 | 小游戏（包括 2048）；遮盖熄屏目前隐藏，取得可靠检测依据后才重评 |

天气依赖未来手机数据链路，不归为缺少天气传感器。板载 IMU 不等于计步算法已完成；PPG、电池和电机等仍有硬件缺口。自动运动识别不做，不取消已确认的基础计步路径。闹钟、倒计时仍保留在原首版计时应用范围，当前增量先完善已可运行的秒表，不由本表悄然取消旧共识。

休眠功耗和 30–60 分钟稳定性长测后置，不作为本轮应用框架前置门槛。RTC 复位丢时按原理图与复位对比单独排查，不暂停应用主线，不把 Flash 中的旧时间当作当前时间。

## 应用菜单与组件页的区别

- **应用布局**：设置中控制从表盘按 KEY1 打开的应用菜单。2026-09-26 用户确认移除产品蜂窝，改为列表和固定三列，默认列表并保存；列表左图标右名称、多列仅图标。选择页参考最新照片，显示“多列布局/列表布局”，选中项为蓝色底＋浅色实心点，未选中无标记；此设置不是组件编辑入口。
- **组件页**：表盘左右滑动环中的页面。一页按固定模板容纳若干组件；长按其中任意组件进入当前页编辑。
- **应用与组件**：组件是对应应用的摘要和入口，共用应用 ID、元信息、能力状态与数据源；配色不产生新应用。普通点击进入对应应用，返回恢复来源组件页/槽位上下文与环位置，KEY1 仍全局回表盘。
- 组件编辑不增加 `设置 → 应用布局` 入口。表盘长按仍只负责表盘更换，受表盘管理开关控制，与组件长按独立。

注册表保留应用标题/图标、应用和组件创建入口、数据提供者、能力状态、卡片/菜单可见性和默认顺序。每种组件声明支持的 `quarter`、`half`、`full` 尺寸，选择器仅展示适合当前槽位的项。能力分为真实可用、占位和不可用，另有具体原因；没有测量结果不能显示演示值。未接入的心率、天气等允许被选入页面，点击进入说明原因的占位应用。

每个槽位保存 `app_id`、独立的 `instance_id`、尺寸和配色 `variant`；同一应用允许在同页、跨页完全重复。`variant` 只表示两种配色，同一尺寸下信息、数据源和跳转目标一致，不提供此前建议的“最近/趋势”二级内容选择。活动、距离、目标等已有摘要种类的内部标识归实施设计，不得将配色字段兼作数据类型，也不因此增加产品选择层级。

## 组件页面及默认值

组件页默认 3 页，最少 1 页、最多 6 页，不包含主表盘。保留包含表盘的左右循环导航。页面顺序与各页槽位独立保存；本轮提供左右插入、整页删除及槽位替换，不增加独立拖动排序、页面隐藏或修改已建页面模板的 UI。

沿用 [固定槽位](UI-INTERACTION.md#311-固定槽位与布局模板)：`quarter` 为 165×174，`half` 为 342×174，`full` 为 342×362。仅四种模板：四个 quarter、上 half 下两个 quarter、上两个 quarter 下 half、单个 full；没有两个 half 的第五种模板。

| 默认页 | 模板与槽位 |
|---|---|
| 1 | 四个 quarter：心率、血氧、电量、压力 |
| 2 | 上 half 活力指标，下两个 quarter 计步、站立 |
| 3 | 上 half 天气，下两个 quarter 睡眠、闹钟 |

十个组件点击后先进入各自的占位应用。Product 中缺失读数显示 `--` 或原因，电量显示已确认的 USB 供电条件；参考照片中的数值不作为产品数据。`ui_demo` 保留旧演示；Product 由持久化配置组合官方 XML 生成的固定尺寸组件，旧 `screen_product_health/activity/daily.xml` 保留为默认页视觉参考。活动、天气支持 half/full，其他八种默认组件支持 quarter；选择器按注册表声明过滤。

页面建立后模板不可修改；更换模板通过删除旧页和新建所需页面完成，操作仍受 1–6 页限制：仅剩一页时先新增，已有六页时先删除。现有槽位不能清空或单独删除；替换必须选择相同尺寸的新组件。允许编辑中的新页面有空槽位，但不能将它提交到正常组件环。

## 组件选择与编辑流程

### 进入与选择

按住组件约 0.7 秒进入“编辑组件”；移动超过约 10 px 取消长按，普通滑动和长按空白不进入编辑。进入后锁定当前页，禁止横向滑动切换其他组件页。

点击槽位进入该尺寸的纵向组件选择页，按应用/组件名称分组展示两种配色预览；直接点选配色即可，不先进入类型页再进入信息内容页。选择完成返回刚才的编辑页，可以继续修改其他槽位。取消选择保留原槽位。

### 已有页面替换

选择替代组件的瞬间应用修改并自动保存，返回原编辑页。已有页不保留等待“完成”的编辑草稿；正常退出无需保存确认。两种配色的信息与应用跳转一致，允许选择重复项。

### 新增页面

1. 在当前页编辑界面点击左侧或右侧 `+`，记录当前页及插入方向。
2. 先选择四种模板之一，再点各槽位选择具体组件与配色。
3. 未填满时勾选按钮置灰；填满后只表示可以提交，不自动建立页面。
4. 点击勾选后保存完整页面，插入进入时当前页的左侧或右侧，正常浏览选中新页面。
5. 无论是否填满，只要尚未点勾，退出均提示“组件编辑未完成，退出将不再保存，确认退出？”；√ 丢弃新页草稿，× 返回继续编辑。

不提供三选项对话框，也不从退出弹窗旁路保存未完成页面。已达 6 页时不得再创建第 7 页，`+` 不可用。

### 删除页面

底部垃圾桶仅删除当前整个组件页。弹一次“是否删除当前小组件？”确认，√ 删除并立即保存新顺序，× 取消。删除前不询问是否保存替换，不叠加保存确认。删除后优先落在前一个组件页；若无前页则选新的第一页。只剩一页时垃圾桶置灰。

### 退出与按键

- 左边缘右滑退出当前编辑层；从选择页返回编辑页。
- 空白区域点击退出只限组件页编辑画布，不扩展为其他页面、列表或整个系统的规则。
- 已有页退出不确认保存；新建页尚未提交的退出按上述 √/× 弹窗处理。
- KEY1 短按以回表盘为目标；如有未提交新页先弹放弃确认，× 留在编辑，√ 丢弃并回表盘。
- 编辑期间 KEY1 长按暂不触发电源操作。

## 保存的实施边界

“立即保存”表示本次选择、确认新建或确认删除即触发持久化，无第二次用户保存动作；不能直接沿用已有亮度设置的 1.5 秒空闲策略并宣称断电安全。实现时需区分保存请求、写入完成和失败，Flash 操作不得阻塞 UI；完成的记录重启后恢复，未提交的新页不写入正式配置。写入中断不能损坏上一次完整布局；失败不能虚报成功。具体编码/迁移方案和测得的保存延迟在实现记录中补充，不将本契约写成已实现保证。

## 设置结构与显示规则

一级顺序参考用户照片：表盘管理、显示与亮度、声音与振动、勿扰模式、消息通知、按键设置、应用布局、电池、系统操作、关于。运动识别和设备密码明确不做并隐藏；其余未支持功能显示状态原因，不提供看似生效的假开关。AOD/默认熄屏样式仅保留未来事项，本期不实现。

| 页面 | 已确认规则 |
|---|---|
| 表盘管理 | 长按开关默认开启并保存；主动更换与表盘长按进入同一选择页。菜单不再保留表盘应用；选中应用并保存、回表盘，未选返回来源 |
| 屏幕亮度 | 手动范围 10%–100%，竖直滑条；默认 60，已有保存值优先，不能覆盖用户的 27。自动亮度先完成光感验证，启用后保留上次手动值、禁用手动滑条，关闭后恢复 |
| 熄屏时间 | 5/10/20/30/60 秒；本轮选定默认总时长 10 秒，选择 60 秒先弹续航提示，√ 提交、× 保留旧值 |
| 变暗与唤醒 | 5 秒采用正常 4 秒加变暗 1 秒；其余最后 5 秒变暗，相对正常亮度约 20%。首次触摸/KEY1 只提亮并消耗完整输入；KEY1 唤醒先落地，单击亮屏须先验证低功耗中断唤醒 |
| 持续亮屏 | 默认关闭，5/10/15/20 分钟均先确认；确认时开始固定倒计时，普通操作不延长。到期重启普通超时，不突然熄屏；主动关闭或重启结束本次状态，控制中心共用并快捷开启 5 分钟 |
| 抬腕/遮盖/AOD | 抬腕占位；遮盖目前隐藏；熄屏显示和默认熄屏样式后续 |
| 声音与振动 | 缺少外接硬件，当前不承诺可提醒；勿扰与消息通知等 BLE 真实通知接入后补齐 |
| 应用布局 | 已实现列表/固定三列，默认列表并保存；产品蜂窝退出选项，完全独立于组件布局 |
| 电池/系统操作 | 真实电池后置；重启、关机、连接新手机、恢复出厂后续 |
| 关于 | 现在可做，显示真实设备信息与固件版本；不编造实物版本/容量 |

Product 自动熄屏已接入并完成主机验证，硬件路径未验收；旧 Bringup 的 10 秒后变暗、再 5 秒熄屏不覆盖本轮。手电筒打开期间保持全亮，退出恢复用户亮度和普通计时；编辑中允许熄屏，但任意时长都恢复现场及未提交新页，豁免两分钟回表盘。普通页与前台运行秒表继续按页面保留契约。RTC/时区、手机同步和连接状态入口仍在后续关联设置范围。

## 实现顺序与首个交付

1. 应用/组件注册表、能力状态、统一路由；默认三页点击进入对应应用，返回恢复来源，保留菜单和 KEY1 行为。
2. 组件配置与保存、新增/替换/删除流程；配色、同尺寸过滤、1–6 页边界、草稿退出和重启恢复。
3. Redmi Watch 4 设置目录和设置模型，表盘管理、亮度、熄屏选项与确认交互；随后接通显示状态机。
4. 补齐秒表、手电筒、设备信息与 RTC 页面；完善心率、天气等正式占位和通知空状态。
5. 接 BLE 连接/重连、手机校时、真实通知收取/删除，Gadgetbridge 累计 8h 上限保留；光感和 IMU 按有界实验逐步接入。
6. 电池、电机、PPG 等硬件到位后推进真实采样、提醒和独立供电；功耗、长期稳定性、AOD 与其他后置能力另验。

首个应用入口增量完成第 1 项；第 2 项已获部分目标板反馈，范围见 STATUS；第 3 项当前通过本机验证，尚待上板。验收分别记录核心/路由测试、Product 与 UI Demo 编译、目标板交互。编辑仍需覆盖重复组件、三种尺寸、取消新建、左右插入、页数上限、单次删除确认及保存恢复。纯文档同步不运行固件构建或 CI。
